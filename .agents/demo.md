# Demo Guidelines

## Demo First

This project is for workshops and demonstrations — not production.

**Prioritize:**
- Visible functionality
- Realistic user journeys
- Polished UI
- Believable sample data

**Do not prioritize:**
- Scalability
- Enterprise architecture
- Advanced optimization

When there is a trade-off between demo value and technical perfection, prefer demo value.

---

## Demo Data

Always use realistic Norwegian-style mock data. The application should feel alive.

**Use:**
- Ola Nordmann, Kari Hansen, Per Johansen, Anne Berg

**Avoid:**
- Lorem Ipsum, User1, Test User, placeholder values

---

## Data Storage

**Use:**
- `localStorage`
- In-memory mock data

**Do not introduce** databases, backend services, or cloud resources unless explicitly requested.

---

## UI Guidelines

- Simple, responsive layouts
- Accessible markup and interactions
- Consistent spacing
- Professional enough to be shown during a seminar
- Norwegian text in all user-facing strings (unless otherwise specified)
